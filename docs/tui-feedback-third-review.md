## Required behavior

Narrowing any mounted view must not crash the dashboard. Fix Shikiru's layout/rendering boundary instead of patching installed Textual/Rich or suppressing exceptions. Preserve drafts, task context, selection, Escape and focus when restoring a usable viewport. The established 20×8 reachability floor remains; preventing failures below that floor does not assert full usability at arbitrary tiny sizes.

Retain reliable normalized tool outcomes when the native protocol supplies them. A failed command is a tool result, not a terminal agent failure. Keep the signal contract additive for existing plugins and older recorded rows. Existing role views and task evidence may show success/failure and an exit code, without adding raw commands, tool output, prompts or filesystem paths. Do not infer why a provider went silent, change stall deadlines, interrupt a quiet turn solely because a tool failed, or fabricate a report. Existing report validation, nudge/rebuild, stall, takeover and same-session handback remain authoritative.

Shikiru's entire project-session status line uses the existing dark palette, including blank fill, status-left/right and selected/unselected window segments. Set session status styles/left/right locally and keep label formats/styles at their documented window scope; leave global defaults and other sessions untouched. Render each actual window index before its existing task title, retaining `0:dashboard` and configured task-name templates without adding `shikiru` to task names. Keep wall time/date with seconds and a four-digit year, and remove the hostname from Shikiru's session chrome. Pane labels retain role, agent/model, iteration, context and ownership/state words; distinguish those parts using the approved steel/primary/secondary and semantic palette colors, without glyph prefixes or heuristic parsing of custom title text. Preserve explicit custom layouts/templates and no-focus-steal behavior.

Popup headers, body text, controls, dropdowns and scrollbar treatments share the approved graphite/surface/steel palette and casing convention. Titles use primary ink with bold emphasis, body copy uses primary ink and secondary explanations use muted text. Ordinary controls use regular primary labels on the surface with straight neutral borders; focus uses the steel accent and selected surface, and disabled controls use muted text. Keep the title and `Esc ×` outside the scroll body, with a consistent separating rule. Use a one-column vertical scrollbar only for overflow; apply straight dropdown borders to both collapsed and expanded native Select states, including focus. Keyboard shortcuts shown on controls must invoke their actual actions, respect disabled/end-of-page states, and preserve native Input/TextArea/Select editing and Escape precedence. No global shortcut may submit a form or consume text unexpectedly.

Choose each popup's initial frame for its content and purpose. Once opened, pagination, filtering, live updates and dropdown expansion must not resize/recenter its outer frame. Controls stay outside the scrolling body and inside the visible frame. Terminal resize may constrain the frame and allow it to regain its initial preferred size when space returns. Keep drafts, reading position, selection and originating context, stationary dashboard underlays and mounted/standalone action compatibility. Share only repeated contracts; introduce no speculative UI framework.

The HTML reference will demonstrate these refinements before the corresponding tmux/popup changes, preserving its palette and the prior reference in Git. Prototype values remain illustrative. Final native review must compare actual rendered coordinates and retained fixture facts rather than using mockup samples or only widget-region/scroll-position assertions.
