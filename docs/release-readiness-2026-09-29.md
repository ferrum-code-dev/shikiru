## Concrete discrepancies corrected

- `README.md` described normal sessions as interactive agent sessions. It now describes headless turns and read-only Rich role views, with native TUI takeover as the interactive path. Its quickstart installs the source checkout using `uv tool install .`.
- `docs/design/02-architecture.md` showed `process` as having no internal imports although it correctly imports typed errors. The layer diagram now shows `errors` below `process`; the process structure inventory remains illustrative.
- `docs/design/05-data.md` claimed `doctor --json` printed merged configuration. It now documents the supported `shikiru --json doctor` form and actual `DoctorReport` payload.
- `docs/design/06-operator.md` conflated engine liveness with database state. It now distinguishes flock-based `engine.lock` liveness from read-only DB progress counts, bounds the tracker scan as implemented, and documents preserved relative paths for nested ignored caches. The remote MCP example puts `--project` before `mcp`; the E2E procedure in `docs/design/07-engineering.md` separates `init --yes` from the later `start` command with global `--set` overrides.
- Sampling and cache intervals were duplicated as named cadence constants. They are operational defaults and now come from `config/defaults.toml` via injected settings, with existing cadences preserved.
- Interactive wizard inputs previously seeded an opaque `default` model. They now seed `agent:` with a blank model, requiring an explicit supported rung and reporting parse/Doctor failures. `init --yes` keeps its documented editable placeholder; no agent catalog or guessed native model was added.
- The inline wizard had an intrinsic-height collapse on a real TTY. Its Screen now receives an 80% viewport height; the quickstart smoke opens it at normal and small dimensions.
- The inline session picker also collapsed its available row height: with two valid sessions, the first installed TTY run displayed only `quickstart`. Its Screen now receives the same bounded viewport height; the private 120×38 and 68×16 checks show both normal rows and navigate to the second row on the small screen. The existing integration tests retain scroll/select and Escape coverage.
- Scheduler dispatch intentionally persists `RUNNING` before task-root and layout setup finishes, while `TaskFlow` writes the first step later. A setup failure can also escalate before the first step. The old strip builder raised for those valid pre-step states; the quickstart attach log showed the home pane dead with a traceback. `operator/strip_views.py` now renders a distinct engine-colored setup panel and the existing escalation panel, preserves hold stamps, and continues to reject `INTEGRATING` without a step. A parameterized real-SQLite `StateDashboardViews` test covers unheld, paused, operator-held and escalated states; the release smoke checks home-pane liveness and absence of traceback after merge.
- The first disposable smoke run reached task submission but the fake turn escalated because its test-only plugin imports `shikiru.agents.testing`, whose package initializer requires `pytest`. The successful rerun installs pytest only into the disposable tool environment alongside the existing fake plugin; Shikiru runtime dependencies are unchanged.
- A real Git-backed detector audit showed nested ignored cache paths were reduced to their basename, so a detected `frontend/node_modules` could target the wrong root path. `ProjectDetectors._caches()` now keeps the repository-relative path, with an integration check against real Git; the wizard docs describe the actual four-component scan and exclusions.
