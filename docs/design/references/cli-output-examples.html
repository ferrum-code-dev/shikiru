Tmux's = prefix is exact-name target syntax, not part of the session name; runtime exact targeting stays unchanged. A remote repair is explicitly labelled to run on that host.

Initializer composition

    
The wizard appears in a neutral dashboard viewport. Its preferred 96×36-cell panel is clamped to the selected terminal size. A normal top row shows cyan-bold SHIKIRU, the white-bold step title and N / 7 counter, followed by the dashboard divider; only the body scrolls. The bottom order is body, static hint, divider, then right-aligned actions. There are no global terminal header or footer rows. The supplied ANSI artwork is embedded as a literal copy, drawn top-left in original terminal-cell positions, unscaled and clipped. Ctrl+F hides the full panel for five seconds, then restores the unchanged state and focus. The shortcut does not intercept typing in editable fields or open combos. Ordinary command examples hide the artwork; the outer review page scrolls without shrinking terminal cells.

    
Repository displays the base and clean or changed worktree plus config destination. Agents keeps all six role/scope rows visible, each with an editable comma-separated ladder field. A dependent Agent/Model/Effort form sits below the scope list and Add appends a supported entry. Blank Implementer Low, Normal and High fields inherit Base; typing or Add creates an override. Multiple Helper entries are a selected proposal that requires later runtime/schema work. Tracker paths are project-relative Markdown files used as task trackers. Cache paths are registered for task worktrees. Path fields start blank; detected candidates add once and can be re-added after manual removal. Empty tracker input sends no tracker files to tasks; empty cache input copies no caches. The CoW row shows simulated filesystem evidence; unsupported CoW skips cache copies.

    
Parallelism states the maximum number of tasks the engine may run at once and shows its default of 2 without Current or Accepted rows. Pre-write Finish preserves the original explanation that it writes .shikiru/config.toml, excludes .shikiru/ in Git, and runs Doctor; it shows the destination and selected summary without redundant Roles or Doctor fact rows. The Run doctor action writes the fixture configuration and displays the full post-write report in Finish, using the native check format: bold white names, grey separators, white detail, then a blank row and aggregate passed/failed line. The result is read-only with Exit and no duplicate report.

    
Drafts persist across steps and logical sizes. Narrow terminal sizes scroll and keep the type size fixed. The left hint is step-specific; Repository has no selection/scroll hint, and scroll appears only when the body overflows. Ctrl+F and 富士山 stay right-aligned on every step. Escape never cancels or exits; explicit Cancel and Exit actions remain. Hints are static and non-focusable. Browser controls stay outside the terminal. Values use text insertion, not HTML markup.
