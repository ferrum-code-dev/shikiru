# Shikiru — Agent Conventions

- **Read first**: `docs/design/` (normative) and your task in `tasks/plan.md`. Do one task at a time; tick its ACs in `plan.md` and the task in `todo.md`.
- **Stack**: Python 3.14, uv. Run `uv run poe check` before every commit; it must be green.
- **Design**: SOLID, KISS, YAGNI. One responsibility per class; pure functions in `domain`; constructor injection; wiring only in `bootstrap.py`. Build nothing beyond the task.
- **Boundaries** (lint-enforced): SQL only in `store`; subprocess only via `process.SubprocessRunner`; time only via `clock.Clock`; agent specifics only in `plugins/agents/*`; the engine imports only `agents.contracts`.
- **Code**: no comments, clear names (a genuinely needed comment uses the in-place marker `# keep: <reason>`, reason required, enforced by `poe comments`); docstrings only on public contracts and their implementations. No literals: tunables go in `defaults.toml`, protocol values and numbers other than 0, 1 and -1 in named module constants; the same `# keep: <reason>` marker excludes a literal; scope in 07 §2 item 5, enforced by `poe literals`. No silent fallbacks, no bare `except`.
- **Tests**: behaviour over implementation. Unit tests only for `domain` rules, models and parsers; integration tests for the rest (real SQLite, git, tmux via `tmux_server`, fake agent). Wait with `wait_until`, time with `FakeClock`, never sleep. No mocks of our own classes, no snapshot spam. Coverage ≥ 80%.
- **Test value**: test domain rules and invariants, not the framework or data shape — no tests for pydantic features (frozen, extra, defaults), enum or constant listings, trivial wiring, or message/description wording. One table per rule. Integration tests assert observable behaviour at boundaries; coverage beyond the gate is not a goal. No screenshot or SVG writes in tests; name tests by behaviour, not task number. Merge per-size or per-route copies that repeat one assertion into one table, with no style-only asserts beyond NO_COLOR cues. In new tests, assert outcomes rather than unsubscribe or wiring, and `wait_until` the observable before asserting, never `pilot.pause()` then assert.
- **Commits**: conventional commits, one logical change each; refactorings in separate `refactor:` commits.
